Setting up your accounts app

This sets up the free online storage that keeps your phone and computer in step. You only do it once.

About 15 minutes. Use a computer rather than your phone.

At the end

You'll send Ryan two bits of text (step 7). He puts them in the app, then sends you the link to open it.

  1. Make a Supabase account

    Go to supabase.com and click Start your project.

    Sign up with your email and a password, then click the link in the email they send you.

    It's free. It won't ask for card details for the free plan.

  2. Create a project

    Click New project and fill in:

    • Name: Bike Accounts
    • Database password: click Generate a password, then copy it somewhere safe. You won't need it day to day, and you should never send it to anyone.
    • Region: London
    • Plan: Free

    Click Create new project and wait a couple of minutes while it sets up.

  3. Add the tables that hold your payments

    In the menu on the left, open SQL Editor. Click the button below to copy the code, paste it into the big box, then click Run.

    create table if not exists public.transactions (
  user_id     uuid not null default auth.uid() references auth.users on delete cascade,
  id          text not null,
  date        date not null,
  description text not null,
  amount      numeric(12, 2) not null,
  category    text,
  source      text,
  import_id   text not null,
  duplicate_of text,
  updated_at  timestamptz not null default now(),
  primary key (user_id, id)
);
alter table public.transactions enable row level security;
drop policy if exists "own transactions" on public.transactions;
create policy "own transactions" on public.transactions
  for all to authenticated
  using ((select auth.uid()) = user_id) with check ((select auth.uid()) = user_id);
create index if not exists transactions_user_date on public.transactions (user_id, date);

create table if not exists public.rules (
  user_id  uuid not null default auth.uid() references auth.users on delete cascade,
  pattern  text not null,
  category text not null,
  primary key (user_id, pattern)
);
alter table public.rules enable row level security;
drop policy if exists "own rules" on public.rules;
create policy "own rules" on public.rules
  for all to authenticated
  using ((select auth.uid()) = user_id) with check ((select auth.uid()) = user_id);

    It should say Success. No rows returned. That's right: there's nothing in it yet.

    It's fine to run this code again if you're not sure it worked. It won't make copies or delete anything.

    Supabase may warn that the query creates tables without row level security. Supabase shows this check when code creates new tables. This code switches row level security on for each table straight after making it (the enable row level security lines), so it's safe to go ahead. If it offers to enable row level security (RLS) for you, accept. Either way, go ahead and run it.

    Then check it worked: open Table Editor in the left menu. You should see transactions and rules, and neither should have a red Unrestricted label. If one does, stop and send Ryan a screenshot.

  4. Create your app login

    In the left menu, open Authentication, then Users. Click Add user, then Create new user.

    • Enter the email and password you want to use to sign in to the app. This can be different from your Supabase password.
    • Tick Auto Confirm User.

    Click Create user. This is the login you'll type into the app on your phone.

  5. Stop anyone else signing up

    Still in Authentication, open Sign In / Providers and turn off Allow new users to sign up. Click Save.

    This matters: it means only the login you just made can get in.

  6. Find the two bits Ryan needs

    Click the cog, Project Settings, at the bottom of the left menu.

    • Project URL: under Data API. It looks like https://abcdefgh.supabase.co
    • Publishable key: under API Keys. It starts sb_publishable_. On some screens it's called the anon public key instead.

  7. Send them to Ryan

    Project URLhttps://….supabase.co
    Publishable keysb_publishable_… (or the "anon public" key)

    These two are safe to send by text or email. On their own they can't get at your payments without your app login.

    Never send anyone
    • the secret key (also called service_role)
    • your database password
    • your app login password

Good to know

On the free plan, Supabase pauses a project if nothing uses it for about a week. Your payments are kept. If the app ever says it can't load your data, sign in to supabase.com, open the Bike Accounts project and click Restore project.
